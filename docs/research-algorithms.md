# 球生成算法与 CPU / CUDA 路线调研

查阅日期：2026-11-03。下文把论文和项目的已有结论、本仓库代码分析、建议实施的方案分别标出。论文的性能排序不视为 AssetSpheres 上的实验结果；本轮实现与基准以仓库对应代码、测试和实验报告为准。

本轮已独立实现 `cover-tight`、单轴 `slab` 和 `refined`（体素 / 原 mesh 标签），并增加 CPU link 并行与可选 CUDA 阶段；测量结果与未实施路线见 [performance.md](performance.md)。下文保留研究建议的推导过程，不将它们自动等同于原作者算法的完整复现。

## 先明确球模型的目标

**本仓库分析。** 一个固定球数预算下有三个不同目标：完整包含机器人以减少漏碰撞、减少向原几何外部突出以减少误碰撞、贴合表面以保持接触位置。它们通常相互竞争。不能仅用表面样本覆盖率选出“最好”的球集：一个足够大的球可以覆盖全部样本，却会有很大的外扩。

对于有平面的盒子，要求每个球完全处于盒子内部时，每个正半径球与盒子某个面平面的交集至多为一个切点。有限球只能覆盖该面上的有限个点，无法覆盖整片二维面。因此，有限内接球无法同时实现零外扩和完整盒子边界覆盖；增加候选点或换 CUDA 不能消除这个几何限制。这是本项目的几何推导，不是论文测得的性能现象。特别是连续平面覆盖，不应由 100% 的有限采样覆盖率替代。

原 `voxel` 的收益只计算新覆盖的内部体素样本；候选半径来自近似内接的 EDT，选择结束后也不移动球心或优化半径。这解释了它可能具有较高体素中心覆盖，但较低原始 mesh 表面覆盖。`cover` 包含完整三角形，其中心却只是簇的面积加权重心，尚未直接最小化包络球半径或原 mesh 之外的体积。

## 一手方法与落地取舍

| 路线 | 已有方法的要点 | 对 AssetSpheres 的判断与优先级 |
| --- | --- | --- |
| 可微中心与半径优化 | MorphIt 联合优化球参数，并用多个损失项和球密度控制平衡覆盖、边界和相互作用 | 优先级高。体素初始化后细化球心与半径；同一采样目标可用 NumPy / SciPy 和 PyTorch CUDA 实现 |
| 变分包络球集 | VSSA 在覆盖约束下交替分组与拟合，直接减少外部体积 | 优先级中高。适合作为保守包络质量基线；实现完整三角积分比当前采样细化复杂 |
| 中轴候选与层次球树 | AMAA 自适应改善中轴近似，再生成多层球包络 | 优先级中。适合多级细节与碰撞粗筛；树结构本身不会减少导出为平坦球数组后的查询次数 |
| 自适应 SDF / 空间细分 | 在不确定区域细分，使用距离界检查覆盖 | 优先级中。用于质量检查、遗漏检测与修复更有价值；应与单纯采样覆盖严格区分 |
| 表面包络球的几何优化 | 本项目 `cover` 的完整三角形归属，配合更小的包围球与误差驱动分裂 | 优先级高，低依赖。能保留已有三角形表面覆盖保证，但仍不自动证明实体内部覆盖 |

### MorphIt

**作者已有工作。** [论文当前 v3](https://arxiv.org/html/2507.14061v3) 将球心和半径作为变量，组合内部覆盖、边界、表面、重叠、包含和法向相关误差，并依据欠覆盖情况调整有效球的分布。作者提供侧重体积、表面和折中的配置；其性能优势是在论文自身数据和评价设置下得到的结果，不能直接推广为本仓库的速度或质量保证。

**依赖与复用。** [作者仓库](https://github.com/HIRO-group/MorphIt-1) 使用 [MIT 许可证](https://github.com/HIRO-group/MorphIt-1/blob/main/LICENSE)。当前 [requirements.txt](https://github.com/HIRO-group/MorphIt-1/blob/main/requirements.txt) 包含 PyTorch、trimesh、rtree、NumPy 和可视化依赖，也固定了较多 CUDA 运行时包。直接安装整套依赖并非最小集成方式。

**我们的建议。** 先实现独立 `refined` 方法，复用体素初始球，优化明确且可测试的覆盖 / 外部误覆盖目标，不把它命名为原生 MorphIt 或宣称复现论文。球数固定时先保留全部预算；自适应增删球另作后续实验。重叠不是必然错误，尤其是保守外包络；过强的重叠惩罚可能破坏窄处和连接处覆盖。

### VSSA

**作者已有工作。** [Microsoft Research 的论文页面](https://www.microsoft.com/en-us/research/publication/variational-sphere-set-approximation-solid-objects/)及其[论文](https://www.microsoft.com/en-us/research/wp-content/uploads/2017/01/sphapprox.pdf)给出一种变分球集近似，围绕物体外部球体积设计误差，并交替分组与球拟合。论文通过三角形积分计算单球外部体积，强调覆盖与贴合的结合。

**我们的建议。** 当前 `cover` 可先对每簇做最小包围球优化，再重新分配完整三角形。每次始终重新取该簇全部三角形顶点的最大距离作为半径，并与原中心择优，可以不丢失表面覆盖且不增加该簇半径；这不等同于完整 VSSA。后续可以用原 mesh 上的误差，决定哪些簇拆分、哪些冗余球合并。论文页面不提供可直接复用代码的许可证，第三方同名实现不能据此视为作者代码。

### AMAA、球树与 FOAM

**作者已有工作。** Bradshaw 与 O'Sullivan 的 [AMAA 论文](https://www.tara.tcd.ie/bitstreams/41e5fba7-6607-45f9-9d35-4e38d963fe95/download)研究自适应中轴近似和球树构造；[作者机构条目](https://gv2.scss.tcd.ie/bibtexbrowser.php?bib=gv.bib&key=DBLP%3Ajournals-tog-BradshawO04)给出 2004 年正式出版信息。层次结构可以让碰撞检查只深入潜在接触区域，而非每次检查全部叶球。

**工具与依赖。** [FOAM 官方项目](https://github.com/CoMMALab/foam)把 URDF 解析、mesh 修正与球树生成组合成机器人处理流程，其[依赖说明](https://github.com/CoMMALab/foam/blob/master/README.md)涉及 Manifold / ManifoldPlus、网格简化与 SphereTree，构建需要 CMake 和原生组件。

**复用边界。** FOAM 顶层标记 MIT，不能据此假定捆绑的全部组件也是 MIT。[SphereTree 的实际 LICENSE](https://github.com/mlund/spheretree/blob/master/LICENSE)授权范围包含教育、研究和非营利用途限制。应将相关代码的来源与条款逐个识别；本轮不把 SphereTree 源码复制进 AssetSpheres。独立实现通用几何思想与直接复用这些软件是不同事情。

**我们的建议。** 先保持对 cuRobo / Lula 的平坦球格式兼容。若后续要做自有批量碰撞引擎，再引入父节点包围球和层次遍历；生成完整树后仅导出固定层，也可以作为球预算不同的多分辨率资产。

## 本轮 `refined` 的可比较目标

以下是本项目建议的实验目标，**不是 MorphIt 原论文目标的完整复现**。定义球并集的覆盖间隙：

```text
g(p) = min_i (||p - c_i|| - r_i)

L = w_inside  E_inside [max(g(p), 0)^2]
  + w_surface E_surface[max(g(q), 0)^2]
  + w_outside E_outside[max(-g(x), 0)^2]
  + lambda * sum_i r_i^3
```

内外样本的损失按组分别归一化，权重表达所选任务的偏好，不把它们直接解释为均匀体积积分。可先对 mesh 尺寸归一化再优化，避免毫米资产与米资产出现不同的优化尺度。半径需使用正参数化或显式下界。

对于由最近球决定的样本，`g` 对球心的梯度为 `(c-p)/||c-p||`，对半径为 `-1`；等距离处可使用次梯度，距离近零时需数值保护。CPU 可以用分块距离和解析梯度，CUDA 可以用同一个目标的张量运算和自动微分。软最小值可以改善多球的梯度分配，但会改变目标，且温度需按几何尺度设置。

外部样本误覆盖损失很重要：只有内部 / 表面覆盖损失时，半径增长即可降低误差。半径正则是辅助约束，不能替代对原 mesh 之外区域的评价。有限采样优化得到的是质量折中，没有连续实体覆盖证书。

## CPU / CUDA 分工

**本项目架构建议。** CPU 适合 URDF / 文件解析、场景展开、mesh 校验、BVH 构建、导出，以及不同 link 的独立任务。CUDA 适合大量点到球距离、候选覆盖矩阵、球选择收益归约、优化迭代和独立的大批量评价。贪心选择球之间有顺序依赖，即使收益计算并行，外层轮次依然是串行的。

针对体素化与 EDT，现有流程并非整体 CUDA 流程。[CuPy 官方 EDT 接口](https://docs.cupy.dev/en/stable/reference/generated/cupyx.scipy.ndimage.distance_transform_edt.html)提供 GPU 欧氏距离变换，可在大栅格且数据留在 GPU 时作为可选路线；仅把小栅格搬到 GPU 做一次 EDT，传输和初始化开销可能抵消收益。这是需要测量的推断，不能仅凭存在 GPU 实现就声称加速。

GPU 任务应避免为每个 link 在不同进程重复创建 CUDA 上下文。推荐 CPU worker 负责准备数据，单个 GPU 执行器批量处理或顺序复用上下文；若 CPU 与 GPU 阶段并行，应记录队列与显存峰值。小 mesh 和低球数下 CPU 距离计算可能更快，需保留显式 CPU 模式。

## 开口 mesh 与“内部”的定义

**已有工作。** [Open3D 距离查询文档](https://www.open3d.org/docs/release/tutorial/geometry/distance_queries.html)明确讨论闭合形状假设；签名距离或占据查询的语义不能从无符号最近距离直接推得。[Fast Winding Numbers 作者项目](https://www.dgp.toronto.edu/projects/fast-winding-numbers/)研究有缺陷的三角 soup 与点云的内外判断，其[作者示例实现](https://github.com/GavinBarill/fast-winding-number-soups)标记 MPL-2.0。

**我们的建议。** 对开口 mesh 默认继续提供表面路径，体积方法必须显式选择修复 / 体积解释策略。若将绕数阈值或壳层厚度定义为“内部”，应把该定义与参数写入报告；它不是原始开放曲面天然具备的唯一实体。不能把修复结果的体积覆盖当作对原始形状无误差的结论。

## 公平评价覆盖与外扩

**本项目评测建议。** 对同一资产、同一球数预算、同一 padding 使用同一批独立验证点。所有方法共用的均匀采样域应包含原 mesh 及全部候选球并集；若采样域只包含 mesh 的包围盒，伸到盒外的球部分会逃过外扩评价。也可以分阶段选定统一的足够大评估域。

在闭合的原始 mesh `M` 与球并集 `S` 上，以相同均匀点统计：

```text
TP = count(M and S)
FN = count(M and not S)
FP = count(S and not M)

volume_coverage        = TP / (TP + FN)
outside_volume_ratio  = FP / (TP + FN)   # 以原 mesh 体积为分母
sphere_precision      = TP / (TP + FP)   # 以球并集体积为分母
IoU                   = TP / (TP + FN + FP)
```

不要仅报告 `FP / 全部 bbox 样本数`：扩大空白采样域会稀释数值。传统 `FPR=FP/非mesh样本数` 也依赖评估域的选择。`sum(4*pi*r^3/3)` 含球重叠重复计量，不是球并集体积。对很稀疏的资产，应增加采样或报告有效内部样本数与不确定性，避免用极少内部点计算貌似精确的比例。

表面需另外给独立样本的欠覆盖率、正间隙均值 / p95 / 最大值，以及能反映球外扩的几何或体积量。比较候选算法时报告覆盖与外扩的 Pareto 关系；单一加权总分可以作任务配置，不能掩盖另一侧明显恶化。

训练、调权与最终测试应分离。若用验证集选迭代次数或权重，应再保留未参与选择的最终测试种子。GPU float32 与 CPU float64 不要求逐位一致，但需要报告精度、随机种子与停止条件，检查最终几何质量处于合理误差范围。

计时同时报告首次调用与预热后的执行时间；区分加载、候选生成、传输、优化、评价和导出。CUDA 计时前后必须同步。端到端加速比与点球距离内核加速比应分别记录；同时记录其他 GPU 任务的负载，避免把已有上下文或并发任务带来的差异混为算法效果。

## 更强的覆盖检查路线

**本项目推导，尚非已实现保证。** 对中心为 `q`、半对角长为 `rho` 的空间 cell，若原 mesh 的可靠有符号距离采用外正内负，且 `sdf_M(q) > rho`，整个 cell 可排除；若 `g(q) <= -rho`，整个 cell 都在某一个球中。其余 cell 继续细分。到深度上限仍不能排除 / 覆盖的 cell 应标为未决，不能报告已证明。实际实现还需考虑距离计算误差与数值裕量。

对于要求固定球数的输出，可用未决区域驱动再优化或球半径修复；若修复必须增加球数，应明确这与原预算的冲突。当前完整三角表面包络的构造性检查比较容易保留，但边界表面被覆盖仍不等于整个实体内部被覆盖。

建议顺序是：先增加独立实体覆盖 / 外扩指标并实现 `refined` CPU / CUDA 同目标对照，再改进 `cover` 的包围球中心；随后探索覆盖驱动重分布、精确 SDF 与自适应证书，最后根据下游查询需求引入完整球树。

## 补充：2026 年 MSS 中轴残差场

**作者已有工作。** [Why the Multi-Sphere Shape Generator Works: Medial-Axis Placement of Spheres](https://arxiv.org/html/2608.15457)（2026-08）研究残差场 `E*=2E−E_tilde`：`E` 为目标形状的距离场，`E_tilde` 为当前多球近似的距离场。论文证明该场的内部局部极大值在连续极限下位于目标形状中轴，并用体素实验研究偏离中轴的尺度。它解释候选放置机制，不是对所有其他生成方法的固定预算全局最优性结论。

**作者实现与依赖。** 对应的[开放 Python 实现 multisphere](https://github.com/FelixBuchele/multisphere)提供 EDT、峰值细化与特征增强残差更新；核心依赖为 NumPy、SciPy、scikit-image 与 trimesh，可选可视化和布尔重建依赖另列。项目使用 GPL-3.0；[软件论文](https://arxiv.org/abs/2604.20002)描述其软件流程。直接复制源码与依据论文独立实现应区别对待，不能把此依赖当成 MIT / Apache 组件。

**我们的判断。** 这条路线适合作为后续“内接球初始化 / 候选生成”的实验基线，并可考虑 GPU 栅格距离变换与归约。当前资料不足以声称它在 AssetSpheres 的机器人 link、固定球数和外扩约束下明显优于 `refined`。应按完整原方法核实残差距离的符号、峰值筛选、中心排斥和终止规则；不能仅替换一行残差公式便声称复现。即使球心更接近中轴，有限内接球与锐边 / 平面完整覆盖的冲突仍然存在。

## 补充：闭合多壳的实体参考并非自动明确

**本项目复现。** `trimesh.is_watertight` 与 `is_volume` 不能排除多个闭合壳的几何相交。把两个相交闭合盒子的三角形直接拼接后，两项检查仍可为真；对整体调用 `mesh.contains` 时，交叠区域按射线奇偶规则可能被归类为外部，而分别查询每个盒子再做逻辑 OR 得到内部。URDF 多个 collision 的几何语义是并集，因此直接把拼接 mesh 的整体奇偶内部当作参考，会错算体积覆盖和外扩。

应保留原始 collision 部件，按部件定义实体后再取并集；或要求显式选择 `union_components` / `parity_shells` 等参考语义。自动把所有闭合组件取并集会填掉嵌套壳的空腔，也不是普遍正确的修复。单一闭合连通壳仍可能自交，连通数、绕向一致与正体积只是必要检查，不构成“无自交”的证明。无法确认参考语义时应跳过实体评价或将其标为基于假设的估计，保留表面指标。
